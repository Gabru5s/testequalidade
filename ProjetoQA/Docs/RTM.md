# Matriz de Rastreabilidade de Requisitos (RTM)

| **ID** | **Categoria**       | **Descrição**                                                        | **Ferramenta/Arquivo** | **Método de verificação**                                       | **Urgência** | **Critério de Aceite**                                                   | **Último resultado** |
|:------:|:-------------------:|:--------------------------------------------------------------------:|:----------------------:|:---------------------------------------------------------------:|:------------:|:------------------------------------------------------------------------:|:--------------------:|
| RNF01  | Manutenibilidade    | A cobertura de testes deve ser de, no mínimo, 80%                    | JaCoCo                 | Caixa Branca: Análise de cobertura de linha e ramos             | Crítica      | O build deve falhar via JaCoCo Check caso a cobertura seja menor que 80% | Pass                 |
| RNF02  | Confiabilidade      | Os testes de persistência não podem utilizar mocks                   | TestContainers/MongoDB | Integração: Execução de testes reais contra um container Docker | Crítica      | Sucesso em todos os testes de integração sem a anotação @MockBean        | Pass                 |
| RNF03  | Qualidade de código | O código deve ser analisado estaticamente para evitar dívida técnica | SonarQube/SonarCloud   | Análise estática: Verificação de bugs e vulnerabilidade         | Alta         | Obter o status "Passed" no Quality Gate do SonarCloud                    | Pass                 |
| RNF04  | Segurança           | As credenciais de acesso devem ser protegidas                        | Spring Security/BCrypt | Caixa Branca: Inspeção do banco de dados e lógica               | Crítica      | Senhas no MongoDB devem ser armazenadas apenas como Hash                 | Pass                 |
| RNF05  | Portabilidade/CI    | O processo de build e teste deve ser totalmente automatizado         | GitHub Actions         | Automação: Execução do pipeline a cada push ou pull request     | Alta         | Pipeline completa (Build, Test, Sonar) deve finalizar com sucesso        | Pass                 |
| RNF06  | Usabilidade         | A interface web deve ser acessível em diferentes tamanhos de tela    | CSS/ThymeLeaf          | Caixa preta: Teste manual de redimensionamento de janela        | Média        | O layout deve se ajustar sem quebra de componentes                       | Pass                 |
| RNF07  | Confiabilidade      | Chamadas a APIs externas devem ser gravadas e reproduzíveis          | VCR                    | Integração: Execução de testes utilizando cassettes gravados    | Alta         | Testes que dependem de rede devem passa mesmo em modo offline            | Pass                 |
| RNF08  | Eficiência          | O gerenciamento de sessão deve ser persistente durante a navegação   | HttpSession            | Caixa Preta: Teste de navegação entre páginas após o login      | Alta         | O usuarioId deve persistir na sessão até que logout seja invocado        | Pass                 |

| RF03   | Segurança     | O sistema deve criptografar a senha antes do usuário salvar                     | AuthController             | POST /Cadastro              | Crítica      | A senha no banco de dados (MongoDB) deve ser um Hash Bcrypt                                                      | 100%          | Pass                 |
| RF04   | Login         | O sistema deve autenticar o usuário validando email e senha                     | AuthController             | POST /Login                 | Crítica      | Se as credenciais estiverem corretas o acesso é liberado; Em caso de erro, deve ser bloquado e dar erro de login | 100%          | Pass                 |

| RF06   | Sessão        | O sistema deve invalidar a sessão ao realizar o logout                          | AuthController             | POST /Logout                | Média        | A sessão deve ser destruída e o usuário redirecionado para /login                                                | 100%          | Pass                 |
| RF07   | Livros        | O sistema deve permitir a criação de livros vinculados ao usuário logado        | LivroController            | POST /api/livros            | Alta         | O livro deve ser salvo com a chave estrangeira do usuarioId da sessão atual                                      | 100%          | Pass                 |
| RF08   | Validação     | O sistema deve impedir o cadastro de livros sem título, autor ou ISBN           | LivroController            | POST /api/livros            | Alta         | Retornar erro amigável caso algum campo obrigatório seja enviado vazio ou nulo                                   | 100%          | Pass                 |
| RF09   | Validação     | O ano de publicação do livro não pode ser futuro ou menor/igual a zero          | LivroController            | POST /api/livros            | Média        | O sistema deve validar o ano contra o Year.now() do servidor                                                     | 100%          | Pass                 |
| RF10   | Regra         | O sistema deve impedir que um usuário cadastre dois livros com o mesmo ISBN     | LivroController            | POST /api/livros            | Alta         | Bloquear o salvamento se existsByIsbnAndUsuarioId retornar verdadeiro                                            | 100%          | Pass                 |
| RF11   | Consulta      | O usuário só deve visualizar a lista de livros que ele mesmo cadastrou          | LivroController            | GET /api/livros             | Alta         | A query no banco deve filtrar obrigatoriamente pelo usuarioId da sessão                                          | 100%          | Pass                 |
| RF12   | Segurança     | O sistema deve impedir que um usuário edite ou exclua um livro de outro usuário | LivroController            | PUT/DELETE /api/livros/{id} | Crítica      | Retornar LivroNaoEncontradoException se o ID do livro não pertencer ao usuarioId                                 | 100%          | Pass                 |
| RF13   | Remoção       | O sistema deve permitir a exclusão definitiva de um livro                       | LivroController            | DELETE /api/livros/{id}     | Média        | O registro deve ser removido do banco de dados após a confirmação                                                | 100%          | Pass                 |
